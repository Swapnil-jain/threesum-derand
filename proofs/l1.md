# L1: a hash-free deterministic route for Exact Triangle, (min,+), APSP and 3SUM

**Theorem L1.** On the word RAM with O(log n)-bit words and integer inputs of magnitude n^{O(1)}, there are deterministic
algorithms for all-edges Exact Triangle, the (min,+) product and APSP (no negative cycles) in n^{3 - S + o(1)} time, and
for 3SUM in n^{2 - S + o(1)} time, where S is the saving certified by `certificates/certify_L1.py`:

| tier | (c, theta, eps, delta) | S >= | 3SUM | ET / (min,+) / APSP |
|---|---|---|---|---|
| exact count + pruned encodings (Appendix A of `derandomisation.md`) | (20.276, 0.10457, 0.05961, 0.027966) | 0.003677999 | O(n^{1.99633}) | O(n^{2.99633}) |
| paper lemmas only | (21.178, 0.10488, 0.05620, 0.026384) | 0.003431999 | O(n^{1.99657}) | O(n^{2.99657}) |

Each O(n^e) takes e strictly above the certified upper end of 3 - S (or 2 - S), so it absorbs the n^{o(1)} factor.

No hashing is used anywhere. The route is a composition of known pieces:
- Chan and Xu's deterministic bit-halving and Fredman reduction for integer Exact Triangle (CX24, Sec. 3, and its
  appendix remark that gives the same for 3SUM through CVX22);
- the comparison-count oracle of Alman and Vassilevska Williams (AVW: Lemma `lem:realred`, Lemma `lem:cmp` after
  Matousek, and the thin-product theorem `thm:singletech` / Cor. `cor:tradeoff`), which supplies the saving;
- Alon and Naor's deterministic witnesses for Boolean products (AN96, Theorem 1, Sec. 2), in place of the random
  sampling steps of CVX22 (their Lemmas 3.4, 4.2, 4.6). Using AN96 witnesses beyond Boolean products is standard
  (Zwick, JACM 2002, for distance products).

What is new is only the composition, and the repair of the two places where it does not go through verbatim
(the 3SUM window in Sec. 5 and the bias in AN96's Claim 7 for 3SUM).

## 1. The oracle

A *comparison count* (AVW, `lem:realred`) has n row lists R_r and n column lists C_c of at most d numbers, each number
with a colour in [d], and a pair set P. For (r, c) in P it asks for gamma(r, c) = the number of pairs (x, y), x in R_r,
y in C_c of the same colour, with x < y (or x <= y). In a *counting call* every list has at most one number per colour,
and there are d comparison counts with disjoint pair sets of total size at most n^2.

**Lemma 1.1 (AVW `lem:cmp`, after Matousek).** For an integer s >= 1 and D'' = ceil(2nd/s) + d, a comparison count
reduces deterministically to one thin product X (n x D'') Y (D'' x n) with entries in {0..d}, evaluated on P, plus
O(n D'' + (|P| + nds + ds^2) log n) time.

**Lemma 1.2 (AVW `thm:singletech` with Cor. `cor:tradeoff`).** For D = N^eps with eps < R_c(gamma), the entries of a
thin product X (N x D) Y (D x N) with integer entries N^{O(1)} on any set W of positions cost
(|W| D^q + N^2 D^{-gamma} + N D^E) N^{o(1)}, with gamma, q, E the closed forms of `certificates/certify.py`
(queries, boxes, encodings). With the exact count + pruned encodings, gamma and E are replaced by gamma_exact and E_pruned.

All counts below are exact integers. Nothing is ever hashed, so no count has a false positive.

## 2. All-edges Exact Triangle

Parts A, B, C of n vertices, weights |w| <= n^nu, S(a,b,c) = w_ab + w_bc + w_ca. Multiply every weight by 4, so that
S = 0 iff |S| <= 3. Write w^l = floor(w / 2^l) (so w^{l+1} = floor(w^l / 2)) and S_l for S with every weight replaced
by w^l. Cut C into n/d blocks beta of d vertices.

**Invariant I_l.** For every pair (a, b) and block beta, piv_l(a, b, beta) is some c in beta with |S_l(a,b,c)| <= 3,
or ⊥ if there is none.

**Lemma 2.1 (floors).** For an integer x, floor(x/2) lies in [x/2 - 1/2, x/2]. Hence S_l/2 - 3/2 <= S_{l+1} <= S_l/2.
*Proof.* Each of the three weights loses at most 1/2. ∎

*Top level.* Take L = ceil(log2(4 n^nu)) + 1. Then every w^L lies in {-1, 0}, so S_L lies in [-3, 0], and any c in beta
is a valid pivot. The base case is free (no Boolean product is needed, unlike CX24's n^omega base).

*Step from l+1 to l.* By Lemma 2.1, |S_l(c)| <= 3 implies S_{l+1}(c) in [-3, 3/2]. So if piv_{l+1} = ⊥, no c in beta
has |S_l| <= 3, and piv_l = ⊥. Otherwise let k = piv_{l+1}. Then delta := S_l(a,b,k) lies in
[2 S_{l+1}(k), 2 S_{l+1}(k) + 3], a subset of [-6, 9], and it is computed directly (n^3/d per level over all entries).
Let W(a,b,beta) = {c' in beta : |S_l(c')| <= 3}. Its size is #(S_l <= 3) - #(S_l <= -4). Since
w_ab = delta - w_ak - w_bk,

  S_l(c') <= t   iff   w_ac' - w_ak  <=  (t - delta) + w_bk - w_bc'        (Fredman's trick),

where w_ab has cancelled. Group the entries (a, b, beta) by (k, delta). For fixed (delta, t), the d groups k in beta
form exactly one counting call: row list {w_ac' - w_ak : c' in beta} for (a, k), column list
{(t - delta) + w_bk - w_bc' : c' in beta} for (b, k), colour c', one number per colour, disjoint pair sets of total
size at most n^2. With 16 values of delta and two thresholds t this is 32 counting calls per block and per oracle use.
If |W| > 0 a new pivot is any element of W, found by Sec. 3. The counts do not depend on which near-witness was the
pivot, so I_l holds.

*Output.* At level 0, piv_0(a, b, beta) != ⊥ iff some c in beta has S(a,b,c) = 0. The edge (a, b) is in a zero
triangle iff some block has a pivot. This is all-edges Exact Triangle.

## 3. Witnesses deterministically: Alon and Naor with a counting oracle

The oracle of Sec. 2 can be restricted to a colour set R (delete from every list the numbers whose colour is outside
R, which a comparison count allows) and returns, for every entry p = (a, b, beta), the integer D_p = |W_p ∩ R|, and
also |W_p ∩ R ∩ Bit_j| for the log d bit classes Bit_j = {c : bit j of the index of c is 1}. That is 2(1 + log d)
Fredman counts of the format above.

AN96 Sec. 2 finds witnesses for all entries of a Boolean product deterministically using exactly two things:
(i) the integer values D_p for diluted sets R, used for the goodness tests (the total sum drops by a factor 3/4, and
at most an alpha fraction of the entries above c reach 0); and (ii) a witness for every entry with D_p = 1, which
AN96 reads off a product with the indices in place of the ones, and which the bit counts give here (the witness index
has bit j set iff the bit count j is 1).

The random variables of AN96 are one bit per colour, shared by all entries. This is the setting of the remark after
their Lemma 2 (one column copied n times). Claims 1-7 use only linearity of expectation and the c-wise eps-dependence
of these bits, never the structure of the witness sets, so they transfer unchanged. AN96 take c = ceil(log log n + 9)
and eps = 2^{-(c+1)}. A phase searches a sample space of size (c log n / eps)^{2+o(1)} = (log n)^{4+o(1)}; the search
visits every point of the space (step 4b needs the whole space checked, so it does not stop at the first good point).
Each point costs one oracle round plus n^3/d goodness bookkeeping. There are O(log n) inner times O(log n) outer
phases. **So the witnesses cost polylog oracle calls per level, deterministically.**

## 4. The (min,+) product and APSP

Per block beta (set w_ab := 0 for the product, and take the entrywise minimum over blocks at the end), let
m_l = min over c in beta of S_l, and let piv be an argmin at level l+1. By Lemma 2.1, m_l >= 2 m_{l+1} and
S_l(piv) <= 2 S_{l+1}(piv) + 3 = 2 m_{l+1} + 3, so j* := S_l(piv) - m_l lies in {0, 1, 2, 3}. The three counts
#{c' : S_l(c') <= S_l(piv) - j}, j = 1, 2, 3, are Fredman counts with no delta grouping
(w_ac' - w_a,piv <= w_b,piv - w_bc' - j), and they determine m_l. Alon and Naor on {c' : S_l(c') = m_l}, grouped by
j*, gives the next argmin. At the top level any pivot is an argmin up to 2, so the same step applies. The minimum over
the blocks costs n^3/d. APSP follows by ceil(log2 n) squarings; entries stay n^{O(1)}. This does not need the
(min,+) -> all-edges Exact Triangle reduction.

## 5. 3SUM

Use the staircase of CVX22 Sec. 3.3 (AVW `lem:realred`(b)): sort A and B, cut them into blocks A_i, B_j of d numbers,
and keep a set Q of O(n^2/d) queries (c, i, j), fixed at level 0 and kept at every level. The pivot of a query is a
pair (k, l) in A_i x B_j. Floors are monotone, so the sorted orders survive halving.

*Window.* In the a + b = c form, S = f(a) + f(b) - f(c) (weights times 4), and floor(-x/2) lies in [-x/2, -x/2 + 1/2],
so S_l/2 - 1 <= S_{l+1} <= S_l/2 + 1/2. Hence |S_l| <= 3 gives S_{l+1} in [-5/2, 2] ("no pivot" passes down), and a
pivot with |S_{l+1}| <= 3 gives delta = S_l in [2 S_{l+1} - 1, 2 S_{l+1} + 2], a subset of **[-7, 8]**: still 16
values, so 32 counts. (The ET window [-6, 9] is wrong here: x = y = -2, z = 3 gives S_l = -7.) At the top level
S_L lies in [-2, 1], so any pivot is valid.

*Counts.* With pivot (k, l): A_i[k'] - A_i[k] <= B_j[l] - B_j[l'] + t - delta, one comparison count of
`lem:realred`(b) per (delta, t), with pair set inside Q.

*Witnesses.* At level l keep one index per distinct value in each A_i and B_j (deleting list entries is allowed, and
witnesses and pivots survive with the same values). Then each k' has at most 7 partners l', and Alon and Naor run on
the bits of k' with multiplicity weights m(k') in [1, 7]. Claim 1 is linear. Claim 2 is applied to entries above 7c,
which have more than c distinct k'. Claim 7 is applied to entries of weight at most 7c; such an entry can have up to
7c distinct k', so "exactly one survives" needs 7c-wise dependence and bias eps' < 2^{-7c}: each of the 2^v
configurations of its v <= 7c variables then has probability >= 2^{-v} - eps' > 0. AN96's eps = 2^{-(c+1)} is too
large here, so the 3SUM run uses **eps' = 2^{-7c-1}**. The sample space becomes
(log n · 7c · 2^{7c+1})^{2+o(1)} = (log n)^{16+o(1)} (since 2^c = Theta(log n)), still polylog. A unique k' is
recognised by every bit count being 0 or the total; then l' is found by binary search in the sorted B_j.

## 6. Cost

Per halving level and per oracle use, with D = n^eps the thin inner dimension and d = n^delta (exponents of n, ET;
3SUM is the same relative to n^2). The block size of Lemma 1.1 is s = 2nd/D, so that D'' = D + d.

| term | cost | saving |
|---|---|---|
| queries | (n/d) · 32 n^2 · D^q | delta - eps q |
| boxes | 32 (n/d) · d · n^2 D^{-gamma} | eps gamma |
| encodings | 32 (n/d) · d · n D^E | 1 - eps E |
| same block (Lemma 1.1) | 32 n · n d s = 64 n^3 d^2 / D | eps - 2 delta |
| ds^2 term | n^3 d^3 / D^2 | 2 eps - 3 delta (implied, as delta <= eps) |
| inner dimension | n^2 D | 1 - eps |
| lists | 32 n^2 d | 1 - delta |
| bookkeeping (pivot sums, goodness tests) | n^3 / d | delta |

There are O(nu log n) levels and polylog oracle uses per level ((log n)^{4+o(1)} sample points per phase for ET and
(min,+), (log n)^{16+o(1)} for 3SUM, times O(log^2 n) phases), so n^{o(1)} in all; the 3SUM bias change does not move
S. `certify_L1.py` encodes every term and side condition (c > 10, 0 < theta < 0.9, 0 < delta <= eps, eps <= 1 + delta,
and Cor. `cor:tradeoff`'s eps gamma < 1 - eps E on the whole arb ball). The binding terms are queries = same block =
boxes. ∎

## 7. Remark: why adaptivity is needed

No oblivious family can replace Alon and Naor's adaptive dilution. Let F be a family of subsets of a block of d points
with |F| <= d/4. Build a set W of d/2 points that meets no member of F in exactly one point. (1) Closure: while some
member has exactly one point that is not forbidden, forbid that point; each member forbids at most one point this way,
so at most d/4 points are forbidden, and afterwards every member has 0 or >= 2 allowed points. (2) Take 2 allowed
points from every member with >= 2 allowed points (at most d/2 points), and pad with allowed points. Every member then
meets W in 0 or >= 2 points, so none isolates a point of W. The closure step is needed: F = {x,z}, {x}, {z} has no W
with 2 points of every member and no singleton. Nothing in Sec. 2-6 depends on this remark.
